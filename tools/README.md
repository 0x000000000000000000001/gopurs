# Tools

The scripts in this directory build, test, measure and release gopurs. They are
plain Node ESM unless noted. `*.test.mjs` files stay at the top level so that
`node --test tools/*.test.mjs` remains the canonical test entry point.

## Guardrails

`check-docs.mjs` verifies relative links, packaged files and module-map coverage.

`check-output-identity.mjs` compares two output trees, or a tree against a
manifest, without parsing the generated Go:

```bash
node tools/check-output-identity.mjs diff <baseline-output> <current-output>
node tools/check-output-identity.mjs snapshot <output> <manifest.json>
node tools/check-output-identity.mjs compare <output> <manifest.json>
```

Use it to check that a rename or move preserves generated files.

## Generated versus handwritten files

| File | Origin |
| --- | --- |
| `bin/gopurs.js` | Spago/esbuild bundle, generated by `npm run build` |
| `src/Gopurs/Runtime/Source.{js,go,rs}` | generated by `build/embed-runtime.mjs` from `runtime/runtime.go` |
| `tools/ffi_gen.wasm` | generated by `build/build-ffi.mjs` from `tools/ffi-gen` |
| `tools/wasm_exec.js` | vendored Go WASM runtime |
| `src/Gopurs/*.{js,go,rs}` (except Runtime) | handwritten FFI, one per `.purs` module |
| `tests/passing-snapshots*/*.go` | generated golden output |

Handwritten FFI must stay in sync with the `foreign import` declarations of its
`.purs` module. The other three host files are not generated from the `.purs`
source; they are maintained manually.

## Conventions

- Resolve the repository root from `import.meta.url`, not from `process.cwd()`.
- Keep test files flat; put helpers in subdirectories.
- Do not write outside a temporary directory in tests; clean up with
  `t.after(...)`.
- A script that changes compiler behaviour needs a matching fixture or contract
  test; a script that only moves files needs the identity check.
- Run `npm run format` after editing a non-test tool; `npm run format:check`
  verifies the result. Tests stay outside the formatter scope.
