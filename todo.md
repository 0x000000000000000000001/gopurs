# Gopurs — Priorités utiles

> **Benchmark : `./bin/go/run -c` dans `altbak.pub`. Ne pas utiliser `./bin/run go` sans argument : il exécute tous les backends.**

Les chiffres marqués « Prototype » viennent de prototypes Go ; les mesures du boxing après intégration dans le compilateur figurent en 2.6. Intégrer et mesurer chaque point séparément. Les régressions doivent rester dans `tests/passing`, avec leurs snapshots Go ; pas de projet de test séparé ni de script de test `.mjs`.

## 2. Spécialiser le boxing des entiers à la frontière FFI

Prototype Arrays, 900 éléments : **15,4 → 9,5 µs**, **1 095 → 15 allocations**, en remplaçant seulement `Box(int64)` par `Int(int64)` dans les wrappers de range et d'addition.

- [x] **2.1** Fixture `tests/passing/FFIIntegerReturns.purs` ajoutée avec FFI Go et JavaScript : 23 assertions couvrent les retours `int64`, `int`, `[]int64`, `[]int`, zéro, négatifs, positifs, bornes PureScript `-2147483648`/`2147483647` et tableaux vides. Retours Go `any` contenant des `int64`, `int`, `string` et `bool` pour protéger le fallback. `./bin/test FFIIntegerReturns -c` et l'exécution JavaScript passent ; snapshot `Main.go` créé et reproduit à l'identique. Les wrappers de `Main_ffi.go`, hors du snapshot standard du runner, ont été relus : `Box(go_res)` et `Box(v)` conservés. Aucun changement du compilateur ni du runner ; seule cette fixture exécutée.
- [x] **2.2** Deux cas exacts ajoutés dans `wrapReturn` de `CodeGen.purs` : `gopurs_runtime.Int(v)` pour `TNamed "int64"`, `gopurs_runtime.Int(int64(v))` pour `TNamed "int"`. Chemins existants conservés pour `any`, `interface{}`, types inconnus et autres types nommés ; éléments des tableaux toujours via `Box(v)`. `./bin/test FFIIntegerReturns -c` passe (23 assertions), snapshot `Main.go` inchangé. Diff de `Main_ffi.go` relu : seuls les deux retours scalaires connus changent, conversions d'entrée et retours dynamiques identiques. Seule cette fixture exécutée.
- [x] **2.3** Sélection partagée dans `boxFfiValue`, utilisée pour les scalaires et les éléments des tableaux : `Int(v)` pour `[]int64`, `Int(int64(v))` pour `[]int`. Diff de `Main_ffi.go` relu : seules les deux expressions de boxing dans les boucles des tableaux changent. Seule cette fixture exécutée.
- [x] **2.4** Fixture étendue à 27 assertions : quatre retours scalaires connus/dynamiques sont consommés par un callback non linéaire passé en argument et lu depuis `Ref`. Relecture : `Int` sur les scalaires et éléments des tableaux connus, `Box` sur les quatre retours dynamiques, conversions d'entrée conservées. Un écart volontaire dans le snapshot FFI provoque bien un échec ; snapshot restauré puis `./bin/test FFIIntegerReturns -c` réussi avec les deux snapshots identiques. - [x] **2.6** `./bin/go/run -c` réussit (28,16 ms sur ce lancement). Gain du boxing confirmé sur le Go régénéré : compilateur actuel avec `boxFfiValue` limité au fallback `Box`, puis spécialisation activée ; regroupement des lambdas conservé dans les deux versions. Go 1.27.0, Apple M4 Pro, `GOMAXPROCS=14`, `GOGC=800`, PGO désactivé. Mesure du cœur `sumEvens` : six échantillons de 1 seconde par version et taille, après six échauffements, ordre A/B alterné et exécutions séquentielles. Résultats vérifiés : `202950` et `2025045000`. Sur cinq paires du programme altbak complet, les 14 résultats sont identiques ; Arrays à 900 passe de 14,75 à 9 µs en médiane des minima « best of 10 ». Le total médian affiché reste stable (26,68 → 26,66 ms), sans gain global mesurable. Go de production final identique à la copie optimisée mesurée ; aucune modification supplémentaire du compilateur.
